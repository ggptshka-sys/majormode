# MajorMode — картинки гитарных аккордов

Windows desktop приложение (MVP), которое рисует аппликатуру аккорда на грифе и сохраняет картинку в **GIF** (основной формат), PNG или JPG.

Сделано в первую очередь для незрячего учителя гитары, который работает через программу экранного доступа: он вводит аккорд, сохраняет картинку и сам вставляет ее в REAPER 5 под песню. Приложение удобно и зрячим пользователям.

> Статус: MVP 0.1.0. Сборка и тесты логики, рендера и экспорта проходят. Работа с NVDA, Экранным диктором и в REAPER 5 **еще не проверялась** на реальном рабочем месте — см. раздел «Что проверено».

## Требования

- Windows 10 или 11, x64.
- Для сборки из исходников: [.NET SDK 10](https://dotnet.microsoft.com/download/dotnet/10.0) — текущий LTS (проект собирался на SDK 10.0.403, `global.json` разрешает любой 10.0.x начиная с 10.0.100).
- Для запуска готового self-contained `.exe` ничего устанавливать не нужно.

## Команды

Все команды выполняются из корня репозитория.

| Действие | Команда |
| --- | --- |
| Запустить приложение | `dotnet run --project src/MajorMode.App/MajorMode.App.csproj` |
| Прогнать тесты | `dotnet test tests/MajorMode.Tests/MajorMode.Tests.csproj` |
| Собрать все | `dotnet build MajorMode.sln -c Release` |
| Собрать `.exe` (папка) | `dotnet publish src/MajorMode.App/MajorMode.App.csproj -c Release -r win-x64 --self-contained true -o publish/win-x64` |
| Собрать один `.exe` | `dotnet publish src/MajorMode.App/MajorMode.App.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -o publish/win-x64-single` |
| Образцы картинок | `dotnet run --project tools/MajorMode.Samples/MajorMode.Samples.csproj -- artifacts/samples --all-formats` (добавьте `--4k` для 4K) |

Готовый файл: `publish/win-x64-single/MajorMode.exe` (около 70 МБ: внутри .NET runtime, WPF и SkiaSharp, сжатие `EnableCompressionInSingleFile`). Нативная библиотека SkiaSharp упакована внутрь exe (`IncludeNativeLibrariesForSelfExtract`), `.pdb` после публикации в Release удаляются. Тот же exe собирается в GitHub Actions и доступен как артефакт `MajorMode-win-x64` у каждого прогона.

## Как пользоваться

Порядок полей сверху вниз совпадает с порядком Tab.

1. **Название аккорда** — любой текст (C, Dm, F#m7, Bb). Гармонически не проверяется. Пишется крупно над грифом.
2. **Палец 1–4: лад и струна.**
   - Лад: 1–24.
   - Струна: 1–6. Для первого пальца можно ввести латинскую **B** (строчная b тоже подходит) — полное баррэ на указанном ладу на все 6 струн. Пример: лад 5, струна B — баррэ на 5 ладу.
   - **Чтобы пропустить палец, введите 0 в оба поля** (подходит и `00`, и пустые поля). Это не открытая струна.
   - Ноль только в одном поле — ошибка. B у пальцев 2–4 — ошибка.
3. **Заглушенные струны** — номера через запятую: `6` или `6,5` (можно пробелы и точку с запятой). Пусто или `XX` (латинские или русские Х) — нет заглушенных.
4. **Ориентация грифа**: вертикально (слева 6 струна, лады сверху вниз) или горизонтально (снизу 6 струна, лады слева направо). Стрелки переключают вариант.
5. **Холст**: 16:9 (1920×1080), 9:16 (1080×1920), и те же в 4K. Не зависит от ориентации.
6. **Стиль изображения**: схематичный, современный темный, реалистичный деревянный. Стиль меняет только оформление.
7. **Формат**: GIF (по умолчанию), PNG, JPG.
8. **Имя файла** — заполняется из названия аккорда, пока вы не впишете свое. Ниже видно итоговое имя.
9. **Выбор пути** — системный диалог выбора папки; текущая папка показана в поле «Текущий путь».
10. **Сохранить** (Ctrl+S). Если файл уже есть, появится стандартный диалог подтверждения перезаписи (по умолчанию «Нет»).

Справа от превью — **Описание аккорда**: полный текст картинки, например «Аккорд F. Баррэ первым пальцем на 1 ладу, все струны. Второй палец: 2 лад, 3 струна. … Отображаются лады 1-5.»

## Что на картинке

- Пальцы — кружки с цифрой: 1 красный, 2 оранжевый, 3 желтый, 4 зеленый. Цифра контрастная к кружку (WCAG ≥ 4.5:1), поэтому цвет — не единственный носитель смысла.
- Баррэ — красная полоса через все 6 струн с цифрой 1.
- Заглушенная струна — красный X со стороны порожка; открытая — кольцо O. Над прижатой струной ничего.
- Приоритет: заглушена > прижата (включая баррэ) > открыта. Если на заглушенной струне стоит палец, показывается X, маркер пальца не рисуется, выводится неблокирующее предупреждение; введенные данные не меняются.
- Номер начального лада: слева от верхнего видимого лада (вертикально) или под левым (горизонтально). Порожек рисуется, когда диапазон начинается с 1 лада.
- Толщина струн убывает от 6 к 1. Текст никогда не поворачивается.

### Автодиапазон ладов

Видно минимум 5 ладов.

1. Есть баррэ и нет пальцев ниже него — старт с лада баррэ (баррэ на 5 ладу → номер 5).
2. Иначе, если все позиции в пределах 1–5 — старт с 1.
3. Иначе — старт с минимального используемого лада.
4. Без пальцев — лады 1–5.

Если позиции занимают больше 7 ладов, картинка не строится и выводится понятная ошибка (ничего не обрезается). Около 24 лада диапазон сдвигается так, чтобы не выходить за 24.

## Архитектура

```
src/MajorMode.Core        модель, парсинг/валидация, автодиапазон, геометрия, описание, имена файлов, настройки (net10.0)
src/MajorMode.Rendering   рендер трех стилей (SkiaSharp) и экспорт GIF/PNG/JPG (net10.0)
src/MajorMode.App         WPF, MVVM, доступность UI Automation (net10.0-windows)
tests/MajorMode.Tests     xUnit: модель, валидация, геометрия, рендер, экспорт
tools/MajorMode.Samples   генерация образцов картинок для ручного просмотра
```

Слои и их ответственность:

| Слой | Где | Что делает |
| --- | --- | --- |
| Model | `Core/Model` | `Chord`, `FingerPlacement`, `ChordRules` (макс. лад 24, видимые лады 5–7), перечисления настроек |
| Parsing/Validation | `Core/Parsing` | `ChordParser`, `MutedStringsParser`: 0/0, B, токены mute, ошибки и предупреждения с привязкой к полю (`FieldId`) |
| Layout/Geometry | `Core/Layout` | `FretRangeCalculator` (автодиапазон), `ChordLayout` (струна/лад → пиксели для обеих ориентаций и любого холста, safe area) |
| Description | `Core/Description` | `ChordDescriber` — текст для screen reader |
| Renderer | `Rendering` | `ChordRenderer` + стили в `Rendering/Styles`. Стиль рисует фон, гриф, лады, струны; маркеры, X/O и текст рисуются общим кодом |
| Export | `Rendering/Export`, `Core/Files` | `GifEncoder`, `ImageExporter`, `FileNameSanitizer` |
| ViewModel/View | `App` | `MainViewModel`, `MainWindow.xaml`, сервисы диалогов, объявлений и настроек |

`ChordAnalyzer` (Core) объединяет разбор, автодиапазон и описание — ViewModel только вызывает его.

### Почему SkiaSharp, а не WPF DrawingContext

Один и тот же renderer нужен для превью и экспорта, а рендер должен быть детерминированным и тестируемым. SkiaSharp (MIT, Microsoft) рисует на CPU в обычный bitmap без UI-потока и STA, поэтому рендер и экспорт проверяются обычными unit-тестами, в том числе в CI. Превью в WPF — это тот же bitmap, просто масштабированный элементом `Image`.

### GIF

Собственный кодер (`Rendering/Export/GifEncoder.cs`) пишет настоящий статический GIF89a: один кадр, глобальная палитра 256 цветов, LZW.

- Палитра: точные цвета маркеров, цифр и текста резервируются, остальное — median cut с минимизацией квадратичной ошибки по числу пикселей.
- Если в картинке ≤ 256 цветов — палитра точная, без дизеринга.
- Иначе режим `Auto`: сначала прямое отображение в палитру; если средняя ошибка мала (плоские стили: схематичный, темный — около 0.01), дизеринг не включается и края текста не шумят. Если заметна (градиентный фон и текстура деревянного стиля — около 0.5, без дизеринга видны кольца-полосы), применяется Floyd–Steinberg змейкой. Порог — `GifEncoder.AutoDitherThreshold`.
- Размер на 1920×1080: схематичный ~20 КБ, темный ~40–70 КБ, деревянный ~400–600 КБ (цена дизеринга, зато без полос).

Встроенный `GifBitmapEncoder` (WIC) не используется из-за слабого квантования; ImageSharp — из-за лицензии Six Labors Split License.

### PNG и JPG

PNG без потерь, JPG с качеством 92, фон всегда непрозрачный. Кодирование через SkiaSharp.

### Имена файлов

`FileNameSanitizer` применяет правила Windows на любой ОС:

- `\ / : * ? " < > |` и управляющие символы → `_`;
- пробелы и точки в конце удаляются;
- зарезервированные имена (`CON`, `PRN`, `AUX`, `NUL`, `COM1`–`COM9`, `LPT1`–`LPT9`) получают суффикс `_` (`CON` → `CON_.gif`);
- расширение `.gif/.png/.jpg/.jpeg`, введенное вручную, отбрасывается — расширение задает формат;
- `#` допустим в Windows и сохраняется: `C#` → `C#.gif`, `Bb` → `Bb.gif`;
- Windows не различает регистр: `Bb.gif` и `BB.gif` — один файл (сработает подтверждение перезаписи);
- пустое имя → `chord`; длина имени до 100 символов; полный путь до 259 символов (классический лимит, чтобы файл открывали и старые программы).

Запись идет во временный файл в той же папке с последующей заменой: при сбое старая картинка не портится. Ошибки «нет прав», «нет папки», «нет места», «файл занят (например, REAPER)» объявляются понятным текстом.

### Настройки

Папка сохранения, ориентация, холст, стиль и формат запоминаются в `%LOCALAPPDATA%\MajorMode\settings.json` (поле `SchemaVersion`, сейчас 1). Сами аккорды не сохраняются. Битый файл настроек игнорируется.

## Доступность

- Только стандартные контролы WPF: `TextBox`, `ComboBox`, `RadioButton`, `Button`.
- У каждого поля: видимая подпись `Label` с `Target`, `AutomationProperties.Name`, `AutomationProperties.HelpText` с подсказкой формата (и текстом ошибки, если она есть), `AutomationProperties.ItemStatus` с ошибкой.
- Ошибки: текст рядом с полем, сводка ошибок и предупреждений (поля только для чтения после кнопки «Сохранить», доступны по Tab).
- Объявления без перевода фокуса: UIA Notification event (`AutomationPeer.RaiseNotificationEvent`) от строки состояния. Ошибки объявляются через 1,5 с после паузы во вводе и только если список изменился; описание аккорда обновляется с задержкой и **не** объявляется автоматически. Результат сохранения объявляется сразу с приоритетом.
- Если программа экранного доступа не озвучивает уведомления, в `UiaAnnouncer` можно включить `UseLiveRegion` (LiveRegionChanged). Оба механизма одновременно не используются, чтобы не было двойного озвучивания.
- Стрелки в группе «Ориентация грифа» выбирают вариант; Tab входит в группу один раз.
- Оформление: темная тема (`Themes/Dark.xaml`) — только шаблоны стандартных контролов, типы элементов и автоматизация не меняются. Контраст текста к фону не ниже 4.5:1. Рамка фокуса — яркая бирюзовая 2 px; поле с ошибкой дополнительно подсвечивается красной рамкой (текст ошибки остается главным признаком).
- В режиме высокой контрастности Windows `ThemeManager` подключает `Themes/HighContrast.xaml`: системные шаблоны и цвета `SystemColors`, переключение на лету.
- Конкретная программа экранного доступа учителя неизвестна. Совместимость не обещается, ниже чеклист для ручной проверки.

### Чеклист ручной проверки: NVDA и Экранный диктор (Narrator)

Проверять в обеих программах на Windows 10/11.

- [ ] При запуске фокус в поле «Название аккорда», озвучиваются имя поля и подсказка.
- [ ] Tab проходит поля строго в порядке: название → пальцы 1–4 (лад, струна) → заглушенные → ориентация → холст → стиль → формат → имя файла → выбор пути → текущий путь → сохранить → (результат / ошибки / предупреждения, если есть) → описание. Shift+Tab — обратно. Ловушек фокуса нет.
- [ ] Каждое поле пальца озвучивается как «Палец N: лад» / «Палец N: струна» с подсказкой про 0/0 (и про B у пальца 1).
- [ ] Группа «Палец N» и «Ориентация грифа» озвучиваются как группы.
- [ ] Стрелки в «Ориентация грифа» переключают вариант, озвучивается выбранный.
- [ ] В выпадающих списках стрелки меняют выбор, озвучивается название пункта (не имя класса).
- [ ] Ввод `0` в лад и `3` в струну: рядом появляется текст ошибки; примерно через 1,5 с после паузы озвучивается сводка ошибок; фокус остается в поле; на каждый символ ничего не объявляется.
- [ ] Исправление ошибки: озвучивается «Ошибок нет».
- [ ] Палец на заглушенной струне: озвучивается предупреждение, данные не меняются.
- [ ] Ctrl+S: озвучивается «Сохранено: <путь>» без перевода фокуса.
- [ ] Повторное сохранение: стандартный диалог перезаписи читается, «Нет» по умолчанию; после ответа фокус возвращается в окно.
- [ ] Сохранение в папку без прав (например, `C:\Windows`): озвучивается понятная ошибка.
- [ ] Поле «Описание аккорда» читается целиком стрелками и командой чтения текущей строки.
- [ ] Access keys (Alt+1…4, Alt+Н и т. д.) переводят фокус в нужное поле.
- [ ] Режим высокой контрастности Windows: все тексты и рамка фокуса видны.
- [ ] Масштаб Windows 150–200%: ничего не обрезается, есть прокрутка формы.

### Ручная проверка в рабочем процессе учителя

- [ ] GIF 1920×1080 и 1080×1920 вставляются в REAPER 5 и отображаются корректно.
- [ ] Цифры и маркеры четкие после вставки в видео.
- [ ] Имена с `#` (например, `C#.gif`) открываются в REAPER 5.

## MVP допущения

- Пустое поле заглушенных, `XX` и `ХХ` (а также любое количество X) означают «нет заглушенных». Пользователем **не подтверждено**.
- Частичного баррэ нет: баррэ только полное и только первым пальцем.
- Максимальный лад 24 (константа `ChordRules.DefaultMaxFret`, правило `ChordRules.MaxFret`).
- Максимум 7 видимых ладов (`ChordRules.MaxVisibleFrets`).
- GIF статический, один кадр.
- Конкретная программа экранного доступа неизвестна, совместимость проверяется позже.
- Палец на заглушенной струне: предупреждение, данные не меняются, на картинке X.
- Два пальца в одной точке — ошибка; два пальца на одной струне на разных ладах — предупреждение.
- Русская «В» в поле струны — ошибка с подсказкой ввести латинскую B (по ТЗ допустима только латинская).
- Пресеты JSON не реализованы (nice-to-have). Если появятся — с полем версии схемы.

## Известные ограничения

- Шрифт: Segoe UI Bold (есть в любой Windows). На других ОС SkiaSharp подставит системный шрифт, поэтому образцы, сгенерированные не на Windows, выглядят чуть иначе.
- Детерминированность гарантируется для одной машины и версии SkiaSharp: одни и те же данные дают побайтно одинаковые пиксели (проверяется тестом).

## Что проверено

- На macOS (Apple Silicon, .NET SDK 10.0.403): сборка всего решения, включая **компиляцию** WPF-проекта и XAML (`EnableWindowsTargeting`); все unit-тесты; образцы картинок просмотрены глазами; GIF открываются системными `sips`/`file` как GIF89a 1080×1920 и 1920×1080.
- В GitHub Actions (`windows-latest`): restore, сборка Release всего решения, все тесты, генерация образцов (просмотрены образцы с Windows-шрифтом Segoe UI), публикация single-file exe.
- UI smoke-тест в CI (`tools/ui-smoke.ps1`): exe запускается, окно появляется, поля заполняются через UI Automation, превью и описание обновляются, ошибка показывается у поля и в строке состояния; скриншоты окна просмотрены; у всех фокусируемых элементов есть имя и подсказка, порядок в дереве совпадает с задуманным порядком Tab. Экран раннера 1024×768.
- **Не проверено**: работа с NVDA и Экранным диктором (озвучка, реальное перемещение по Tab, объявления), режим высокой контрастности и масштаб 150–200%, диалоги выбора папки и перезаписи, вставка GIF в REAPER 5.
