# MajorMode — для разработчиков

Пользовательское описание — в [README](../README.md).

## Требования

- Windows 10 или 11, x64.
- [.NET SDK 10](https://dotnet.microsoft.com/download/dotnet/10.0) (LTS). `global.json` разрешает любой 10.0.x начиная с 10.0.100.

## Команды

Все команды выполняются из корня репозитория.

| Действие | Команда |
| --- | --- |
| Запустить приложение | `dotnet run --project src/MajorMode.App/MajorMode.App.csproj` |
| Прогнать тесты | `dotnet test tests/MajorMode.Tests/MajorMode.Tests.csproj` |
| Собрать все | `dotnet build MajorMode.sln -c Release` |
| Собрать `.exe` (папка) | `dotnet publish src/MajorMode.App/MajorMode.App.csproj -c Release -r win-x64 --self-contained true -o publish/win-x64` |
| Собрать один `.exe` | `dotnet publish src/MajorMode.App/MajorMode.App.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -o publish/win-x64-single` |
| Образцы картинок | `dotnet run --project tools/MajorMode.Samples/MajorMode.Samples.csproj -- artifacts/samples --all-formats` (добавьте `--4k` для 4K) |

Готовый файл: `publish/win-x64-single/MajorMode.exe` (около 70 МБ: внутри .NET runtime, WPF и SkiaSharp, сжатие `EnableCompressionInSingleFile`). Нативная библиотека SkiaSharp упакована внутрь exe (`IncludeNativeLibrariesForSelfExtract`), `.pdb` после публикации в Release удаляются. Тот же exe собирается в GitHub Actions.

## Правила ввода

- Лад 1–24. Струна 1–6; у пальца 1 латинская `B`/`b` — полное баррэ на все 6 струн. B у пальцев 2–4 — ошибка.
- `0/0` (а также `00` и пустые поля) — палец пропущен. Ноль только в одном поле — ошибка.
- Заглушенные: номера через запятую, допускаются пробелы и точка с запятой. Пусто или `XX` (латинские или русские Х, любое количество) — нет заглушенных.
- Палец на заглушенной струне: предупреждение, данные не меняются, на картинке X.
- Два пальца в одной точке — ошибка; два пальца на одной струне на разных ладах — предупреждение.
- Русская «В» в поле струны — ошибка с подсказкой ввести латинскую B.

## Что на картинке

- Цифра в кружке пальца контрастная к кружку (WCAG ≥ 4.5:1), цвет — не единственный носитель смысла.
- Приоритет: заглушена > прижата (включая баррэ) > открыта. Над прижатой струной ничего.
- Номер начального лада: слева от верхнего видимого лада (вертикально) или под левым (горизонтально). Порожек рисуется, когда диапазон начинается с 1 лада.
- Толщина струн убывает от 6 к 1. Текст никогда не поворачивается.

### Автодиапазон ладов

Видно минимум 5 ладов.

1. Есть баррэ и нет пальцев ниже него — старт с лада баррэ.
2. Иначе, если все позиции в пределах 1–5 — старт с 1.
3. Иначе — старт с минимального используемого лада.
4. Без пальцев — лады 1–5.

Если позиции занимают больше 7 ладов, картинка не строится и выводится ошибка (ничего не обрезается). Около 24 лада диапазон сдвигается так, чтобы не выходить за 24.

## Архитектура

```
src/MajorMode.Core        модель, парсинг/валидация, автодиапазон, геометрия, описание, имена файлов, настройки (net10.0)
src/MajorMode.Rendering   рендер трех стилей (SkiaSharp) и экспорт GIF/PNG/JPG (net10.0)
src/MajorMode.App         WPF, MVVM, доступность UI Automation (net10.0-windows)
tests/MajorMode.Tests     xUnit: модель, валидация, геометрия, рендер, экспорт
tools/MajorMode.Samples   генерация образцов картинок для ручного просмотра
```

| Слой | Где | Что делает |
| --- | --- | --- |
| Model | `Core/Model` | `Chord`, `FingerPlacement`, `ChordRules` (макс. лад 24, видимые лады 5–7), перечисления настроек |
| Parsing/Validation | `Core/Parsing` | `ChordParser`, `MutedStringsParser`: 0/0, B, токены mute, ошибки и предупреждения с привязкой к полю (`FieldId`) |
| Layout/Geometry | `Core/Layout` | `FretRangeCalculator` (автодиапазон), `ChordLayout` (струна/лад → пиксели для обеих ориентаций и любого холста, safe area) |
| Description | `Core/Description` | `ChordDescriber` — текст для screen reader |
| Renderer | `Rendering` | `ChordRenderer` + стили в `Rendering/Styles`. Стиль рисует фон, гриф, лады, струны; маркеры, X/O и текст рисуются общим кодом |
| Export | `Rendering/Export`, `Core/Files` | `GifEncoder`, `ImageExporter`, `FileNameSanitizer` |
| ViewModel/View | `App` | `MainViewModel`, `MainWindow.xaml`, сервисы диалогов, объявлений и настроек |

`ChordAnalyzer` (Core) объединяет разбор, автодиапазон и описание — ViewModel только вызывает его.

### Почему SkiaSharp, а не WPF DrawingContext

Один и тот же renderer нужен для превью и экспорта, а рендер должен быть детерминированным и тестируемым. SkiaSharp (MIT, Microsoft) рисует на CPU в обычный bitmap без UI-потока и STA, поэтому рендер и экспорт проверяются обычными unit-тестами, в том числе в CI. Превью в WPF — это тот же bitmap, просто масштабированный элементом `Image`.

### GIF

Собственный кодер (`Rendering/Export/GifEncoder.cs`) пишет статический GIF89a: один кадр, глобальная палитра 256 цветов, LZW.

- Палитра: точные цвета маркеров, цифр и текста резервируются, остальное — median cut с минимизацией квадратичной ошибки по числу пикселей.
- Если в картинке ≤ 256 цветов — палитра точная, без дизеринга.
- Иначе режим `Auto`: сначала прямое отображение в палитру; если средняя ошибка мала (плоские стили), дизеринг не включается и края текста не шумят. Если заметна (градиент и текстура деревянного стиля), применяется Floyd–Steinberg змейкой. Порог — `GifEncoder.AutoDitherThreshold`.
- Размер на 1920×1080: схематичный ~20 КБ, темный ~40–70 КБ, деревянный ~400–600 КБ.

Встроенный `GifBitmapEncoder` (WIC) не используется из-за слабого квантования; ImageSharp — из-за лицензии Six Labors Split License.

### PNG и JPG

PNG без потерь, JPG с качеством 92, фон всегда непрозрачный. Кодирование через SkiaSharp.

### Имена файлов

`FileNameSanitizer` применяет правила Windows на любой ОС:

- `\ / : * ? " < > |` и управляющие символы → `_`;
- пробелы и точки в конце удаляются;
- зарезервированные имена (`CON`, `PRN`, `AUX`, `NUL`, `COM1`–`COM9`, `LPT1`–`LPT9`) получают суффикс `_`;
- расширение `.gif/.png/.jpg/.jpeg`, введенное вручную, отбрасывается — расширение задает формат;
- `#` сохраняется: `C#` → `C#.gif`;
- Windows не различает регистр: `Bb.gif` и `BB.gif` — один файл (сработает подтверждение перезаписи);
- пустое имя → `chord`; длина имени до 100 символов; полный путь до 259 символов.

Запись идет во временный файл в той же папке с последующей заменой: при сбое старая картинка не портится. Ошибки «нет прав», «нет папки», «нет места», «файл занят» объявляются понятным текстом.

### Настройки

`%LOCALAPPDATA%\MajorMode\settings.json` (поле `SchemaVersion`, сейчас 1): папка сохранения, ориентация, холст, стиль, формат. Битый файл настроек игнорируется.

### Обновление программы

Обновление по кнопке, без сервера, авторизации и телеметрии.

- Каждый push в `main`, прошедший сборку, тесты и UI smoke-тест, публикует GitHub Release `v0.1.<номер сборки>` с файлами `MajorMode.exe` и `MajorMode.exe.sha256`. Хранятся последние 10 релизов. Коммиты только с документацией — с `[skip ci]`, чтобы не выпускать релиз.
- «Проверить обновления» делает один публичный запрос `GET api.github.com/repos/ggptshka-sys/majormode/releases/latest` (с уникальным параметром в обход минутного кэша CDN). Автоматических проверок нет.
- Если версия новее — диалог с подтверждением. После «Да»: exe скачивается рядом с текущим, сверяется SHA-256, текущий переименовывается в `MajorMode.exe.old`, новый встает на его место и запускается с `--updated-from`. Новая версия удаляет `.old` и объявляет «Программа обновлена».
- При любой ошибке программа остается прежней и сообщает причину.
- Работает только для single-file exe из релиза; при `dotnet run` кнопка сообщает, где скачать версию вручную.
- CI проверяет сквозной сценарий (`tools/update-e2e.ps1`): скачивает предыдущий релиз, нажимает кнопку, подтверждает диалог, проверяет замену и перезапуск.

## Доступность

- Только стандартные контролы WPF: `TextBox`, `ComboBox`, `RadioButton`, `Button`.
- У каждого поля: `Label` с `Target`, `AutomationProperties.Name`, `HelpText` с подсказкой формата (и текстом ошибки), `ItemStatus` с ошибкой.
- Ошибки: текст рядом с полем и сводка ошибок (поле только для чтения после «Сохранить», доступно по Tab).
- Объявления без перевода фокуса: UIA Notification event (`AutomationPeer.RaiseNotificationEvent`) от строки состояния. Ошибки объявляются через 1,5 с после паузы во вводе и только если список изменился; описание аккорда **не** объявляется автоматически. Результат сохранения объявляется сразу.
- Если программа экранного доступа не озвучивает уведомления, в `UiaAnnouncer` можно включить `UseLiveRegion` (LiveRegionChanged). Оба механизма одновременно не используются.
- Стрелки в группе «Ориентация грифа» выбирают вариант; Tab входит в группу один раз.
- «Поделиться» и «Проверить обновления» — кнопки, оформленные как ссылки (`LinkButton`), в строке состояния; объявлены последними в разметке, поэтому последние по Tab.
- Темная тема (`Themes/Dark.xaml`) — только шаблоны стандартных контролов. Контраст текста не ниже 4.5:1, рамка фокуса 2 px.
- В режиме высокой контрастности `ThemeManager` подключает `Themes/HighContrast.xaml` (системные цвета), переключение на лету.

### Чеклист ручной проверки: NVDA и Экранный диктор

- [ ] При запуске фокус в поле «Название аккорда», озвучиваются имя поля и подсказка.
- [ ] Порядок Tab: название → пальцы 1–4 (лад, струна) → заглушенные → ориентация → холст → стиль → формат → имя файла → текущий путь → выбор пути → сохранить → (результат / ошибки, если есть) → описание → поделиться → проверить обновления. Shift+Tab — обратно.
- [ ] Поля пальцев озвучиваются как «Палец N: лад» / «Палец N: струна» с подсказкой про 0/0 (и про B у пальца 1).
- [ ] Стрелки в «Ориентация грифа» переключают вариант, озвучивается выбранный.
- [ ] В выпадающих списках озвучивается название пункта.
- [ ] Ошибка ввода: текст у поля; через ~1,5 с озвучивается сводка; фокус остается в поле. Исправление — «Ошибок нет».
- [ ] Ctrl+S: озвучивается «Сохранено: <путь>» без перевода фокуса. Диалог перезаписи читается, «Нет» по умолчанию.
- [ ] NVDA+End / Диктор+End читает строку состояния.
- [ ] «Поделиться» (Alt+Д): открывается браузер, озвучивается, что ссылка скопирована.
- [ ] «Проверить обновления» (Alt+Б): озвучивается проверка и результат; после обновления — «Программа обновлена…».
- [ ] Высокая контрастность и масштаб 150–200%: всё видно, ничего не обрезается.

### Проверка в рабочем процессе учителя

- [ ] Имена с `#` (например, `C#.gif`) открываются в REAPER 5.

## Ограничения и допущения

- Частичного баррэ нет: баррэ только полное и только первым пальцем.
- GIF статический, один кадр. Пресетов нет.
- Шрифт Segoe UI Bold; на других ОС образцы выглядят чуть иначе.
- Детерминированность — для одной машины и версии SkiaSharp (проверяется тестом).
- exe не подписан: при первом запуске скачанного файла SmartScreen показывает предупреждение.

## Что проверено автоматически

- CI (`windows-latest`): сборка Release, все тесты, образцы картинок, single-file exe, UI smoke-тест (`tools/ui-smoke.ps1`: запуск, ввод через UI Automation, скриншоты, список фокусируемых элементов), сквозной тест обновления.
- Не проверено автоматически: озвучка NVDA и Экранным диктором, вставка в REAPER 5.
