# Как дорабатывать MajorMode

Небольшие изменения, по одному за раз. Для каждого изменения:

1. **Изменение.** Ветка от `main`, понятное название (`fix/mute-parsing`, `feat/json-presets`).
2. **Тесты.** Новая логика — новый тест в `tests/MajorMode.Tests`. Перед коммитом:
   ```
   dotnet build MajorMode.sln -c Release
   dotnet test tests/MajorMode.Tests/MajorMode.Tests.csproj
   ```
   Изменили рендер — сгенерируйте образцы и посмотрите их глазами:
   ```
   dotnet run --project tools/MajorMode.Samples/MajorMode.Samples.csproj -- artifacts/samples --all-formats
   ```
3. **Ручная проверка доступности** (если меняли UI): пройдите чеклист NVDA / Экранного диктора из README хотя бы для затронутых полей. Не пишите «проверено», если не проверяли.
4. **Документация.** Обновите README (если поменялось поведение или команды) и раздел `[Unreleased]` в CHANGELOG.

## Правила архитектуры

- Модель, геометрия, оформление и экспорт разделены: `Core` не знает про SkiaSharp и WPF, `Rendering` не знает про WPF.
- Новый стиль — новый класс в `src/MajorMode.Rendering/Styles`. Стиль рисует только фон, гриф, лады и струны; аппликатуру (маркеры, цифры, X/O, номер лада) не меняет и цифры в кружках не убирает.
- Цвет нигде не единственный носитель смысла.
- Только стандартные контролы WPF; у каждого поля `Label` с `Target`, `AutomationProperties.Name` и `HelpText`.
- Формат данных не меняется без учета совместимости. Сохраняемые JSON (настройки, будущие пресеты) содержат `SchemaVersion`; старые версии должны читаться.
- В MVP не добавляются авторизация, сервер и телеметрия. Обновление — только по кнопке и с подтверждения пользователя (см. README, «Обновление программы»); тихих фоновых обновлений нет.
- Каждый push в `main` публикует релиз, который получит учитель. Перед push убедитесь, что CI на ветке зеленый.
- Личные пути и данные пользователей в репозиторий не коммитятся.
